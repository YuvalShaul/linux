# Old vs. new commands: net-tools (`ifconfig`) vs. iproute2 (`ip`)

**Prerequisite:** [0-linux-networking-basics.md](0-linux-networking-basics.md) — remember the key distinction there: these commands talk to the **kernel's current state**. They are *runtime* tools, not configuration files — nothing they change survives a reboot.

If you learned networking on older Linux (or from older tutorials, or from macOS), you know `ifconfig`, `route` and `netstat`. Modern Linux replaced that whole toolbox. This lesson maps old to new, and explains why the change happened.

### Two toolboxes
| Toolbox | Package | Status |
|---|---|---|
| **net-tools** | `ifconfig`, `route`, `netstat`, `arp`, ... | **Deprecated** since ~2009. Not even installed by default on modern Ubuntu/RHEL — if `ifconfig` works on your machine, someone installed it |
| **iproute2** | `ip`, `ss`, `bridge`, `tc`, ... | The standard. Preinstalled everywhere |

You still need to *read* net-tools: countless scripts, docs and StackOverflow answers use it, and other Unixes (macOS, BSD) still ship `ifconfig`. But everything you *write* should use iproute2.

### The translation table
| Task | Old (net-tools) | New (iproute2) |
|---|---|---|
| Show interfaces + addresses | `ifconfig` | `ip addr` (or `ip a`) |
| Show one interface | `ifconfig ens33` | `ip addr show dev ens33` |
| Interface up / down | `ifconfig ens33 up` | `ip link set ens33 up` |
| Set an IP address | `ifconfig ens33 192.168.1.50 netmask 255.255.255.0` | `ip addr add 192.168.1.50/24 dev ens33` |
| Show routing table | `route -n` | `ip route` (or `ip r`) |
| Add default gateway | `route add default gw 192.168.1.1` | `ip route add default via 192.168.1.1` |
| ARP table (neighbors) | `arp -n` | `ip neigh` |
| Listening sockets | `netstat -tlnp` | `ss -tlnp` |
| All connections | `netstat -an` | `ss -an` |
| Interface statistics | `netstat -i` | `ip -s link` |
| Bridges | `brctl show` | `bridge link` |

Note the pattern: iproute2 is **one command with subcommands** (`ip addr`, `ip link`, `ip route`, `ip neigh`) instead of a pile of separate binaries. Each subcommand can be abbreviated (`ip a`, `ip r`, `ip n`).

### Side by side: reading the output
Old:
```
$ ifconfig ens33
ens33: flags=4163<UP,BROADCAST,RUNNING,MULTICAST>  mtu 1500
        inet 192.168.111.50  netmask 255.255.255.0  broadcast 192.168.111.255
        ether 00:0c:29:3a:5b:7c  txqueuelen 1000  (Ethernet)
```
New:
```
$ ip addr show dev ens33
2: ens33: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc fq_codel state UP
    link/ether 00:0c:29:3a:5b:7c brd ff:ff:ff:ff:ff:ff
    inet 192.168.111.50/24 brd 192.168.111.255 scope global ens33
```
Two things to notice in the new output:
- **CIDR notation** (`/24`) instead of a separate `netmask 255.255.255.0` field.
- **Layers are separated:** `link/ether` is the L2 line (MAC), `inet` is the L3 line (IP). `ip link` shows only L2; `ip addr` adds L3.

### Why was net-tools replaced?
Not for cosmetics — `ifconfig` has real limitations:

1. **It can't show everything.** `ifconfig` predates several kernel features. The classic trap: an interface with **multiple IP addresses** — `ip addr` lists them all, `ifconfig` shows only the first one. You can stare at `ifconfig` output and *not see* an address that is actively answering pings.
2. **Old kernel interface.** net-tools talks to the kernel through legacy `ioctl` calls; iproute2 uses **netlink**, the modern kernel networking API — the same one NetworkManager and systemd-networkd use. What `ip` shows is what the managers see.
3. **One toolbox for everything modern.** Policy routing (`ip rule`), network namespaces (`ip netns` — the foundation of container networking), tunnels, VRFs, multiple routing tables — none of these exist in net-tools at all.

`netstat` → `ss` is the same story: `ss` reads socket info directly from the kernel and is dramatically faster on busy servers with thousands of connections.

### The one thing both toolboxes share
Neither is persistent. Whether you type `ifconfig ens33 192.168.1.50 ...` or `ip addr add 192.168.1.50/24 dev ens33`, the kernel obeys — until reboot, or until the network manager reapplies its own configuration over yours. For persistent changes, go back to [0-linux-networking-basics.md](0-linux-networking-basics.md): find who manages the interface, and configure *that* (e.g. `nmcli` in [1-nm-config.md](1-nm-config.md)).

### Summary
- **net-tools** (`ifconfig`, `route`, `netstat`, `arp`) is deprecated and often not even installed; **iproute2** (`ip`, `ss`) is the standard.
- Learn to *read* the old commands, but *write* only the new ones.
- `ip` uses netlink (same API as the managers), understands CIDR, multiple addresses, namespaces and policy routing — things `ifconfig` can't even display.
- Both toolboxes only touch **runtime kernel state** — persistence is the manager's job.
